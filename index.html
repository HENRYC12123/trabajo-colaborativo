        01
        
Fundamentos

        
Antes de teclear comandos, entiende las piezas.

      


      

        

          
¿Qué es Git?

          
Un sistema de control de versiones distribuido. Guarda "fotos" (commits) del estado de tu proyecto para que puedas volver atrás, comparar cambios y trabajar en paralelo.

        

        

          
¿Qué es GitHub?

          
Una plataforma en la nube que aloja repositorios Git y añade colaboración: Pull Requests, Issues, revisiones de código, Actions (CI/CD) y herramientas de IA.

        

        

          
Git ≠ GitHub

          
Git funciona en tu computadora sin internet. GitHub es uno de varios servicios remotos (también existen GitLab o Bitbucket) donde compartes ese historial.

        03
        
Ramas y flujo de trabajo

        
Trabaja en paralelo sin romper la rama principal.

      


      

        

          
          
          
        


        

          
    
            
  1. Actualiza main: git switch main && git pull
    2. 
            
  2. Crea tu rama: git switch -c feature/login
    3. 
            
  3. Haz commits pequeños y con mensajes claros.
    4. 
            
  4. Sube la rama: git push -u origin feature/login
    5. 
            
  5. Abre un Pull Request en GitHub y pide revisión.
    6. 
            
  6. Fusiona cuando pase la revisión y las pruebas, luego borra la rama.
    7. 
          

          
        


        

          

            

              
git merge

              
Crea un commit de fusión y conserva el historial tal como ocurrió. Seguro para ramas compartidas.

              git switch main
git merge feature/login
            

            

              
git rebase

              
Reescribe tus commits encima de otra rama, dejando un historial lineal. Úsalo solo en ramas que no hayas compartido.

              git switch feature/login
git rebase main
            

          

        


        

          
Un conflicto aparece cuando dos ramas cambian las mismas líneas. Git marca el archivo así:

          

            

<<<<<<< HEAD
const saludo = "Hola";
=======
const saludo = "Buenas";
>>>>>>> feature/saludo

          

          
    
            
  1. Edita el archivo, deja la versión correcta y borra los marcadores.
    2. 
            
  2. git add archivo.js
    3. 
            
  3. git commit (o git rebase --continue si estabas en un rebase).
    4. 
          

          
💡 Con IA: pega ambas versiones en tu asistente y pídele que explique qué intenta hacer cada una antes de decidir. Tú eliges el resultado final.

        

      

    


    
    

      

        04
        
Trabajar en GitHub

        
Las piezas de colaboración que usarás a diario.

      


      

        

          Crear y conectar un repositorio
          

            

git init
git add .
git commit -m "chore: commit inicial"
git remote add origin https://github.com/usuario/mi-proyecto.git
git push -u origin main

          

          
Con la CLI oficial puedes hacerlo en un paso: gh repo create mi-proyecto --public --source=. --push

        

        

          Pull Requests (PR)
          
Un PR propone fusionar una rama en otra. Incluye una descripción, la lista de cambios, comentarios de revisión y el estado de las pruebas automáticas.

          
    
            
  • Mantén los PR pequeños y enfocados en un solo objetivo.
    • 
            
  • Explica qué cambia y por qué; enlaza el issue relacionado (Closes #42).
    • 
            
  • Desde la terminal: gh pr create --fill
    • 
          

        

        

          Issues y Projects
          
Los Issues registran errores, ideas y tareas. Con etiquetas, responsables e hitos organizas el trabajo; Projects los muestra en tableros tipo kanban.

        

        

          GitHub Actions (CI/CD)
          
Automatiza pruebas, linters y despliegues con archivos YAML en .github/workflows/.

          

            

name: CI
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 20
      - run: npm ci
      - run: npm test

          

        

        

          .gitignore y secretos
          
Nunca subas contraseñas, tokens ni archivos .env. Añádelos a .gitignore. Si se filtró un secreto, revócalo de inmediato: borrarlo en un commit nuevo no lo elimina del historial.

        

      

    


    
    

      

        05
        
Git + IA: tu copiloto

        
Dónde la IA aporta valor real en el ciclo de desarrollo.

      


      

        

          ✍️
          
Mensajes de commit

          
Pide a la IA que lea tu git diff --staged y proponga un mensaje con formato Conventional Commits. Revísalo y ajústalo antes de confirmar.

        

        

          🔍
          
Revisión de código

          
Usa asistentes para una primera revisión del PR: errores probables, casos borde, nombres confusos. No reemplaza la revisión humana, la complementa.

        

        

          🧩
          
Resolver conflictos

          
La IA explica qué intenta cada lado del conflicto y sugiere una combinación. Ejecuta las pruebas después de aceptar cualquier propuesta.

        

        

          📄
          
Descripciones de PR

          
Genera un resumen de los cambios, el motivo y cómo probarlos a partir del diff de la rama. Ahorra tiempo y mejora la comunicación del equipo.

        

        

          🤖
          
Agentes en la terminal

          
Herramientas como GitHub Copilot, Claude Code o Cursor pueden crear ramas, editar archivos y ejecutar comandos. Pide que te muestren el plan y revisa cada cambio.

        

        

          🎓
          
Aprender Git

          
¿No entiendes un error o un comando? Pide una explicación con ejemplos. Es como tener un tutor paciente disponible siempre.

Buenas prácticas con IA

      

        

          
✅ Haz

          
    
            
  • Lee y entiende cada línea antes de hacer commit.
    • 
            
  • Ejecuta pruebas después de cambios generados.
    • 
            
  • Da contexto: archivos relevantes, objetivo, restricciones.
    • 
            
  • Trabaja en una rama para poder descartar todo con facilidad.
    • 
            
  • Revisa licencias si la IA sugiere código muy específico.
    • 
          

        

        

          
⛔ Evita

          
    
            
  • Pegar tokens, contraseñas o datos de clientes en el chat.
    • 
            
  • Aceptar comandos destructivos (reset --hard, push --force) sin entenderlos.
    • 
            
  • Commits gigantes de "la IA lo arregló todo".
    • 
            
  • Dar a un agente permisos de escritura sin supervisión en ramas protegidas.
    •
